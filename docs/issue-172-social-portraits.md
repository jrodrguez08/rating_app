# Issue #172: social portrait decoding

## Confirmed failure and scope

The published projection resolves reviewed aliases to canonical Players, uses the canonical persisted photo (source identity only as a missing-value fallback), and preserves the immutable result ranking, averages and MVP set. Only its top three Players enter `loadSocialPlayerPhotos`; the Story and Open Graph routes both use that helper and `PublishedPodiumImage`. Full-ranking Stories intentionally omit photographs. Root social cards and browser/Studio avatars do not use this helper.

A deterministic 150×150 JPEG served at the existing allowlisted `.png` URL with `Content-Type: image/png` reproduced the fault in the real Next.js `ImageResponse` engine. The old helper labeled it `data:image/png`. Rendering it alone produced 22,500 transparent pixels. The identical bytes labeled `data:image/jpeg` produced the expected opaque photograph color. The old podium rendered an image whenever that mislabeled URL existed, so neither the photograph nor initials painted. This is a renderer failure despite successful HTTP and browser decoding.

A separate read-only request to the reported public photo on November 8, 2026 returned HTTP 200, `image/png`, 7,647 bytes, and a decoded 150×150 JPEG, matching the issue evidence. A representative local Saprissa Story using those exact bytes now visibly renders N. Williams in second place with 8.6; A. Madriz 8.9 and D. Sequeira 7.6 retain first/third place and initials. This composition uses synthetic Match/result inputs, not production Firestore or a captured production response. No production application fix is claimed before deployment.

## Validation and fallback contract

The helper retains the exact HTTPS API-Sports player-path allowlist, rejects redirects, keeps the three-second fetch timeout and existing fetch cache policy, accepts only PNG/JPEG response declarations, and enforces the two-megabyte limit against both declared and streamed bytes. Actual format comes from Sharp's byte parser, never the header or `.png` suffix. A strict complete decode rejects malformed/truncated payloads; a four-million-pixel limit bounds decompression. Only PNG and JPEG remain supported. Sharp was already locked as Next.js's optional dependency; declaring the same 0.35.4 version directly makes the runtime decoder explicit without introducing another imaging library. Valid bytes are preserved with their detected MIME, with no conversion or persistent cache.

Preparation failure omits the photo from the shared map. Both podium formats keep deterministic, high-contrast initials underneath the positioned portrait as additional protection if the server renderer cannot paint it. No browser image-error event is required. Dimensions, medals, club theme, names, ratings and order are unchanged. Transparent photo pixels can reveal the initials underneath; opaque identification photographs cover them.

No Firestore reads/writes, provider API calls, migration, index, secret, background task or retry is added. Errors remain local fallback outcomes without logging remote URLs or provider responses. The download cap now stops excess streaming before buffering the entire response.
